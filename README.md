# signals-core
Библиотека обработки сигналов

## Назначение
Библиотека предметной логики для работы с одноканальными сигналами: хранение сигнала, запись и чтение csv-файлов, офлайн и онлайн фильтрация скользящим средним, детектирование выходов сигнала за границы допустимого диапазона.

Библиотека не зависит от пользовательского интерфейса и собирается самостоятельно, без приложения.

## Состав репозитория
- `SignalProcessing.Core.sln` – решение библиотеки
- `SignalProcessing.Core` – проект библиотеки классов (Class Library)
- `SignalProcessing.Core.Tests` – проект модульных тестов библиотеки (xUnit)

## Состав библиотеки
| Класс | Назначение | Исключения |
|---|---|---|
| `SingleChannelSignal` | Одноканальный сигнал: массив значений `Data` и частота квантования `Frequency` в герцах. Свойство `TimeTick` возвращает моменты времени отсчетов в секундах. | `ArgumentNullException` – массив значений равен `null`.<br>`ArgumentOutOfRangeException` – частота равна нулю или отрицательна. |
| `SingleChannelSignalWriter` | Запись сигнала в текстовый csv-файл: в первой строке частота в герцах, в каждой следующей одно значение. Дробная часть всегда отделяется точкой. | Собственных проверок нет. Если файл нельзя создать или записать (нет каталога, нет прав, файл занят), выбрасываются стандартные исключения работы с файлами: `IOException`, `UnauthorizedAccessException`, `DirectoryNotFoundException`. |
| `SingleChannelSignalReader` | Чтение сигнала из csv-файла того же формата, что создает `SingleChannelSignalWriter`. | `InvalidDataException` – файл пуст, какая-либо строка не является числом или частота не положительна; в сообщении указан номер ошибочной строки.<br>`FileNotFoundException` – файл не найден. |
| `OfflineFilter` | Сглаживание всего сигнала сразу скользящим средним с окном, центрированным на отсчете. За краями сигнала повторяются первое и последнее значения. Исходный массив не изменяется. | `ArgumentNullException` – массив значений равен `null`.<br>`ArgumentOutOfRangeException` – размер окна не положителен или четен. |
| `OnlineFilter` | Сглаживание сигнала скользящим средним по мере поступления отсчетов: сигнал можно подавать частями, результат не зависит от разбиения. Учитываются только текущий и предыдущие отсчеты, поэтому результат запаздывает относительно офлайн-фильтра. Метод `Reset` начинает обработку нового сигнала. | `ArgumentOutOfRangeException` – размер окна, переданный в конструктор, не положителен.<br>`ArgumentNullException` – в `Filter` передан `null`. |
| `SingleChannelRangeAnalyzer` | Поиск участков, где сигнал выходит за допустимый диапазон [min, max] не меньше заданного числа отсчетов подряд. О каждом найденном участке сообщает событием `OutOfRange` с номерами первого и последнего отсчета участка (`OutOfRangeEventArgs`). | Явно не выбрасывает. Аргументы не проверяются. |
| `SignalOperations` | Операции над несколькими сигналами одной частоты. `Sum` – поэлементная сумма, длина результата равна длине самого длинного сигнала, короткие сигналы за своей длиной считаются нулевыми. `Concat` – склейка сигналов друг за другом в порядке следования. Исходные сигналы не изменяются. | `ArgumentNullException` – список равен `null` или содержит `null`.<br>`ArgumentException` – список пуст или частоты сигналов различаются больше чем на 1e-5 Гц (в сообщении указаны обе частоты). |
| `CircularBuffer<T>` | Циклический буфер фиксированной емкости: хранит последние добавленные элементы, при заполнении новый элемент записывается на место самого старого. Добавление и обращение по индексу выполняются за постоянное время. Индекс 0 – самый старый элемент. | `ArgumentOutOfRangeException` – емкость не положительна; индекс меньше 0 или не меньше числа хранимых элементов. |
| `Resampler` | Пересчет сигнала на новую частоту квантования линейной интерполяцией между соседними отсчетами. Результат не выходит за интервал времени исходного сигнала. | `ArgumentNullException` – сигнал равен `null`.<br>`ArgumentOutOfRangeException` – новая частота равна нулю или отрицательна. |
| `OfflineMedianFilter` | Медианный фильтр для всего сигнала сразу: каждое значение заменяется медианой окна, центрированного на отсчете. Убирает одиночные выбросы и не размывает резкие перепады. Края обрабатываются как в `OfflineFilter`. | `ArgumentNullException` – массив значений равен `null`.<br>`ArgumentOutOfRangeException` – размер окна не положителен или четен. |
| `OnlineMedianFilter` | Медианный фильтр по мере поступления отсчетов, окно хранится в `CircularBuffer<float>`. Сигнал можно подавать частями, результат запаздывает относительно офлайн-фильтра. Метод `Reset` начинает обработку нового сигнала. | `ArgumentOutOfRangeException` – размер окна, переданный в конструктор, не положителен или четен.<br>`ArgumentNullException` – в `Filter` передан `null`. |
| `ExponentialSmoothingFilter` | Онлайн-фильтр экспоненциального сглаживания: каждый выход сдвигается от предыдущего выхода к новому отсчету на долю `alpha`. Чем больше `alpha`, тем быстрее реакция; при `alpha` = 1 выход равен входу. Метод `Reset` начинает обработку нового сигнала. | `ArgumentOutOfRangeException` – `alpha` не больше 0 или больше 1.<br>`ArgumentNullException` – в `Filter` передан `null`. |

## Анализ пересечений порога
Класс `ThresholdAnalyzer` ищет в сигнале пересечения заданного порога. Пересечение вверх (`Up`) – переход от значения ниже порога к значению не ниже порога, пересечение вниз (`Down`) – обратный переход. Значение, равное порогу, относится к верхней области. Маркер `SignalMarker` ставится на отсчет, на котором произошел переход.

На каждое найденное пересечение анализатор вызывает событие `MarkerDetected` (паттерн Observer). Аргументы события `MarkerDetectedEventArgs` содержат сигнал, маркер, время отсчета в секундах и значение сигнала в этом отсчете. После просмотра всего сигнала метод `Analyze` возвращает `SignalAnalysisResult` – сигнал и список всех маркеров, доступный только для чтения. Анализ работает и без подписчиков, исходный сигнал не изменяется.

Исключения `Analyze`: `ArgumentNullException` – сигнал равен `null`; `ArgumentOutOfRangeException` – порог равен NaN или бесконечности; `ArgumentException` – среди отсчетов сигнала есть NaN или бесконечность. При ошибке события не генерируются.

## Запуск тестов
Тесты находятся в проекте `SignalProcessing.Core.Tests` решения `SignalProcessing.Core.sln` и используют пакеты NuGet:
- `xunit` 2.9.3 – атрибуты тестов и класс `Assert` (версия 3 – `xunit.v3` – с проектами .NET Framework этого типа не работает);
- `xunit.runner.visualstudio` – запуск тестов из Visual Studio;
- `Microsoft.NET.Test.Sdk` – инфраструктура запуска тестов.

Пакеты подключены в формате PackageReference и скачиваются автоматически при первой сборке, отдельно устанавливать их не нужно.

Порядок запуска в Visual Studio:
1. Открыть `SignalProcessing.Core.sln`.
2. Собрать решение: Build → Build Solution.
3. Открыть окно Test → Test Explorer и нажать Run All Tests.

Пройденные тесты отмечаются зеленым, не пройденные – красным. Отдельный тест можно запустить или отладить из контекстного меню в Test Explorer.

## Связанные репозитории
Библиотека используется приложением из репозитория
https://github.com/blzxc/signals-generator-app

Оба репозитория клонируются в один родительский каталог, рядом друг с другом, под своими именами:

```
C:\talanov\
├── signals-core\
└── signals-generator-app\
```

Решение SignalGenerator.sln из репозитория signals-generator-app ссылается на проект библиотеки
по относительному пути ..\signals-core\SignalProcessing.Core\,
поэтому имена каталогов и их расположение изменять нельзя: иначе решение приложения не откроется.

Сама библиотека собирается самостоятельно, без приложения: достаточно открыть SignalProcessing.Core.sln.
